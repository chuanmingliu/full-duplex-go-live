# Simulator workbench and task evaluation

Implement the user's requested feature expansion before pushing `codex/inbound-user-simulator`. The interactive design demonstration is deferred. This document is the binding feature specification and execution plan.

References: [golive](https://github.com/chuanmingliu/full-duplex-go-live/tree/telephony-realtime), [LiveKit Agent Simulations](https://livekit.com/blog/testing-voice-agents-with-agent-simulations). LiveKit informs task-oriented scenarios and independent evaluation; it is not a runtime dependency. Both voice runtimes listen and speak concurrently; the assistant originates calls and the simulated customer receives them.

## Global constraints

- Work only in the isolated full-duplex-go-live clone on `codex/inbound-user-simulator`. Do not change the openai-gpt-live checkout, remote hosts, existing services, gateway routing, provider accounts or production configuration. Do not place calls or make paid model requests during development.
- Preserve audio-only inter-agent conversation, exact run/call/session binding, single active reservation, finite deadlines, synthetic defaults and no outbound dial endpoint. Never substitute the current/latest run for an explicit run ID.
- New scenario fields are optional and backward compatible with schema_version 1. Existing scenarios without added fields must retain their original canonical prompt and scenario hashes.
- Credentials remain environment-owned. Never expose resolved provider configuration, keys, media/webhook tokens, private endpoint URLs or arbitrary file paths through panels, responses or logs. The control token may be entered into the loopback workbench and held only in memory; never URL, disk, localStorage or sessionStorage.
- Transcript retention is opt-in. Post-call transcript/evaluation access must preserve that gate and report truncation. Unknown/missing/invalid evidence must never produce a passing semantic grade.
- A mock/SIP transport pass is not proof of speech quality, successful task completion, carrier readiness or a real Claude conversation. Label evidence accordingly. Carrier integration remains pending.
- No new runtime dependencies unless needed; prefer existing Go standard library, embedded static HTML/CSS/JS and existing test tools. Each source file stays comfortably below 1,000 lines.
- Record tests and limitations. Do not regenerate previous measured SIP evidence or claim new carrier/provider validation. New local tests use fixtures or loopback fake services.

## Task 1: Task scenarios, honest reports and evidence retrieval

Ownership: `internal/simulator` only, plus new scenario examples under `scenarios/simulator` (do not change existing fixture scenarios' content). Add focused behavior tests. Other workers own CLI and UI; do not edit their files.

1. Add optional Scenario `goal` (string), `behavior` ([]string), `expectations` ([]Expectation with `id` and `description`), and `expected_outcome` (empty/`conversation`/`cancel_before_answer`). Validate nonempty supplied strings, safe unique expectation IDs, at most 16 behavior instructions and 16 expectations, goal/behavior entries <=2,000 chars, expectation descriptions <=2,000 chars; retain total 64 KiB bound. Document byte versus rune limits consistently. Default remains conversation.
2. Include goal and behavior in the customer prompt only when present; expectations and expected_outcome belong exclusively to evaluation/control and MUST NOT be inserted into the live persona prompt. Existing prompt output remains byte-identical when new prompt fields are absent.
3. Add optional report metadata: scenario_id, expected_outcome, termination_reason, transcript_truncated. Default to false for older reports' truncation field. Mark transcript truncation when the existing 256-entry cap drops any entry; retain existing redaction. Unknown restored/aborted evidence is indeterminate.
4. Expected cancellation reports must validate actual native pre-answer cancellation confirmation, no answer/greeting, no speech, clean termination and no run failures. Do not turn unrelated failure/expiration/stop into cancellation success. Conversation reports retain answered_once/greeting_once. Add specific expectation checks for cancel scenarios rather than marking ordinary successful calls as cancelled. Existing scenarios default unchanged.
5. Add authenticated `GET /sim/v1/runs` returning a bounded list of Snapshot values, deterministic newest-first order with a stable tie-break; no raw persona or transcript. Include restored runs and retain the 128-run storage bound. Return list wrapper `{runs:[...]}`.
6. Add authenticated terminal-only `GET /sim/v1/runs/{id}/transcript`, via controller method `Transcript(ctx,id) (TranscriptArtifact,error)`. Envelope fields: schema_version=1, run_id, scenario_hash, prompt_hash, truncated, entries ([]TranscriptEntry). Enforce report TranscriptRetained gate, including restored runs; disabled is explicit conflict, nonterminal conflict, missing 404. Support restart reading bounded private transcript.json; never retrieve arbitrary paths. Read copies under controller lock; return independent slices. Do not return the opt-in transcript through other API responses.
7. Export scenario hash helpers needed by clients/evaluation, keeping canonical JSON behavior consistent (suggest `ScenarioHash(Scenario) string`, `PromptHash(Scenario) string`). Export no secrets.
8. Add new synthetic task scenario (appointment correction) with a goal, behavior instructions, private facts and judge expectations, explicitly retain_transcript=true so evaluation is possible. Add a pre-answer cancel scenario with expected_outcome=cancel_before_answer, a sufficiently long answer delay, and retain_transcript=false. These are examples, not test claims.
9. Add authenticated non-mutating `POST /sim/v1/validate`: strict DecodeScenario validation and `{scenario, scenario_hash, prompt_hash}` response, without reservation or effects. UI uses this for strict imports and edits; tests cover auth, malformed/duplicate/unknown JSON and absence of created runs.
10. Resolve the literal `<run_id>` placeholder in Snapshot.dial_target_reference to that snapshot's exact run ID. Leave unrelated configured references unchanged. Clients support both resolved URI and old template responses, validating the final called SIP user matches the owned run.
11. Scripted hangup completion requires both successful stop effects and matching observed termination. Command acceptance alone is insufficient. Until effects settle, snapshots remain nonterminal, reports stay unavailable and the reservation remains occupied, including synchronous callbacks. Restart cannot convert pending evidence into success. Preserve original scenario fixtures; a new suite-local busy example schedules hangup before duration/idle limits so its requested actions have a reachable passing path.

Tests: backward-compatible hashes/prompt; all new validation boundaries and duplicate IDs; expectation isolation from prompt; authenticated list/transcript endpoints, copying and restart retention behavior; truncation becomes visible; expected native CANCEL passes correct checks while expiration, generic ended, answered and failed variants do not. Run simulator package race tests. Commit only owned files and write task report.

## Task 2: Repeatable inbound suites and independent post-call evaluation

Ownership: new `internal/simclient`, `internal/simeval`, `cmd/golive-simctl`, and `scenarios/suites` files only. Consume Task 1's interfaces. Other workers own core and UI. Do not edit receiver or shared engine.

Implement a small documented CLI with subcommands `suite` and `evaluate`, not a broad framework.

### Inbound suite

- `suite --file PATH --url http://127.0.0.1:18865 --token-env SIM_CONTROL_TOKEN --output DIR` reads a strict JSON manifest: schema_version=1, id, repeat (1..10), scenarios (list of paths relative to manifest, 1..32); cap total runs at 100. Reject malformed, duplicate/unknown JSON fields and invalid scenario inputs before any network action. Include an example with two existing synthetic scenarios.
- Create one reservation at a time through the existing authenticated API and fresh invocation/trial idempotency keys. Emit one flushed JSON-lines `ready` record for each reservation (run_id, scenario_id, trial, exact called SIP URI using the returned dial_target_reference). Claude/the independent caller consumes this record and originates the call; the suite runner must never dial or execute shell hooks.
- Await terminal state, fetch report, persist sanitized per-run report and suite summary privately (0600 files, 0700 new directories), then continue. No auto-retries of new reservations/calls. Bound HTTP requests, response bodies, polling and total run wait; cancellation stops ONLY the currently created exact run through a short bounded cleanup context, not any pre-existing run. Do not create later runs after cancellation or ambiguous/failed preparation.
- Distinguish protocol checks from semantics. Summaries have pass/fail/indeterminate counts, run IDs, scenario IDs/hashes and repetitions; a transport-only suite cannot label task expectations as passed. CLI exit 0 only when requested checks truly pass, nonzero for fail/indeterminate or operational error; document exit codes. Existing hardcoded semantic placeholder checks must not make every transport-only suite fail: explicitly select lifecycle/action checks for protocol verdict and report semantic verdict separately; scenarios with expectations remain task-indeterminate until evaluated.
- Reject HTTP redirects (token leakage), URL credentials, query/fragment endpoints and non-http(s). HTTP is allowed only for literal loopback/localhost; external control requires HTTPS. Error text must not disclose tokens, endpoint response bodies or transcript. Testing uses httptest only.

### Independent evaluator

- `evaluate --scenario PATH --report PATH --transcript PATH --output PATH` reads scenario + report + Task 1 transcript envelope and validates IDs, hashes, retention, terminal report, no truncation, bounded valid normalized assistant/customer turns and expectations BEFORE contacting any provider. Input bounds: each file <=1 MiB, transcript <=256 entries, nondecreasing nonnegative timestamps, only assistant/customer roles. Empty/one-sided transcript, invalid/missing evidence or no expectations => indeterminate; no provider request and nonzero exit. Do not accept mismatched artifacts.
- Optional explicit OpenAI-compatible judge configuration comes from `SIM_EVAL_BASE_URL`, `SIM_EVAL_MODEL`, `SIM_EVAL_API_KEY`; no credentials shared implicitly with voice runtime. Append `/chat/completions` to a documented base ending in `/v1` (or preserve a documented full endpoint consistently). HTTPS except loopback; reject redirects, credentials, query/fragment and bounded timeout/body. No requests unless the `evaluate` command is invoked with valid evidence/configuration.
- Judge system instructions define it as independent, treat transcript content as untrusted conversation data, judge ONLY the remote assistant against scenario expectations, not the simulated customer. Send task/facts/expectations separately from role-labeled utterances. No tool calls or actions.
- Require strict structured JSON verdicts per expectation (exactly each ID once, result pass/fail/indeterminate, concise reason, evidence_turns with 1-based transcript indices). Passing/failing decisions require valid evidence indices; reject unknown IDs, invalid indices, malformed JSON, duplicates and refusal/partial output as indeterminate. Do not treat a keyword match as semantic proof.
- Emit a separate evaluation artifact with schema_version, run_id, scenario_hash, prompt_hash, transcript hash, judge model, prompt version, per-expectation grades and aggregate pass/fail/indeterminate. Never overwrite the raw run report. Missing evidence dominates pass; any fail => fail, otherwise any indeterminate => indeterminate. Sanitize/bound provider reasons and never save the raw judge completion or credentials. Keep communication errors generic. Explain that LLM judging is fallible; deterministic protocol evidence remains separate.

Tests: strict manifests, repetitions and sequential ready/terminal ordering; 401, conflicts, malformed/oversized responses, redirects, timeout and cancellation stopping only owned run; output permissions and no secret logs. Fake judge covers role separation, exact-ID/indices validation, injection-like transcript, mismatch/truncation/missing-evidence no request, provider errors and independent artifact. No live API calls. Race-test new packages and CLI; build. Commit owned files and write task report.

## Task 3: Essential simulator configuration panels

Ownership: new `internal/simulatorui` assets/handlers/tests, `cmd/golive-simulator/main.go` integration, and new Go embed helper under `scenarios/simulator` for the JSON examples. Do not edit core controller, CLI/evaluator or existing ordinary web/index.html.

- Serve a self-contained embedded workbench at `/sim/` only in golive-simulator. Root may redirect there; leave media/webhook routes intact. No external scripts/fonts/CDNs or cross-origin calls. Add restrictive CSP (external self scripts/styles, no unsafe-inline), nosniff and no-store. Render all scenario/report/provider-derived text with textContent, never HTML interpolation.
- Implement authenticated `GET /sim/v1/config` and `/sim/v1/scenarios` through a simulator-only handler before the generic controller route. Use constant-time token comparison and explicit safe DTOs; never serialize config.Config. Config fields may include ASR/LLM/TTS names, backend model, voice, language, speed, client rate, barge-in mode and enabled simulator constraints; readiness status is a separate probe with timeout. No provider base URLs, arbitrary paths, server secrets or raw config. Presets use embedded checked-in JSON and don't mutate files.
- Authentication panel: password input for SIM_CONTROL_TOKEN, connect/disconnect; hold only in JS memory, no browser storage or URL token, clear on disconnect and never export it. No microphone permission, outbound call button, arbitrary service URL, or credential editor.
- Scenario panel: presets, scenario ID, language, persona, goal, synthetic facts (JSON object), greeting, behavior list, semantic expectations, opt-in transcript retention. Import/export strict scenario JSON with visible validation errors. Do not silently discard unsupported/unknown imported fields. A scenario must pass backend validation when prepared.
- Call behavior panel: answer delay, duration, idle timeout, remote-turn limit, expected outcome, scheduled actions (bounded structured JSON is acceptable for actions). Clearly expose existing interruption trigger/occurrence/offset/hold semantics. Provide cooperative, confused, busy, appointment correction and cancel presets.
- Voice/provider panel: show effective running settings; editable next-start profile controls for provider names/model/voice/language/speed and supported barge-in values. Export a credential-free simulator-compatible profile. Clearly label draft vs active settings and `restart of this isolated simulator required`; never apply a profile or restart anything automatically. Preserve fixed private-network/simulator guards; do not offer arbitrary provider endpoints or unsafe capabilities. Reuse existing provider choices (mock vs tencent/deepseek/minimax) and valid cut/finish_sentence/queue values from repository source, verifying actual names.
- Run panel: prepare scenario, show exact returned run ID and called SIP target plus expiry; no calling from browser. Refresh/list recent runs; select explicit run; monitor state/events with bounded polling and cursor/truncation handling; stop only selected explicit run after user action. Polling aborts/clears on disconnect, view change and terminal state. Authentication errors return to disconnected state. Surface gateway readiness separately from HTTP reachability.
- Results panel: lifecycle/action checks, audio-boundary latency samples with invalid reasons, failures, semantic indeterminate state. Download report and opt-in transcript envelope for independent CLI evaluation, never imply mock tones prove conversation success. Report errors visibly. Export is explicit; no automatic transcript fetch/retention.
- Accessible responsive interface, native labels and buttons, meaningful disabled/busy states, works at 375px and desktop. Keep actual UI concise and user-facing. This is a functional management tool, not the postponed architectural demonstration.

Tests: backend auth and safe DTO serialization (including injected secret sentinel values); embedded assets/CSP and preset validity; UI browser test with a loopback fake server exercises connect, preset edits, import errors, scenario/profile export, prepare exact target, select/stop exact run, report/transcript gating and disconnect. Verify mobile overflow and no console errors, no network requests outside local test server. Tests must not place SIP/carrier/provider calls. Commit owned files and write task report.
